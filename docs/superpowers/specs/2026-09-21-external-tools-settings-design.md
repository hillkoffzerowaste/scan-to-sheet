# ตั้งค่าหมวดเครื่องมือภายนอก

## เป้าหมาย

ให้ Firebase Admin จัดการหมวดเครื่องมือภายนอกและลิงก์ได้จากในแอป โดยเพิ่ม แก้ไข และลบหมวดเดิมหรือหมวดใหม่ได้ รวมถึงเพิ่ม แก้ไข และลบลิงก์ในแต่ละหมวด การเปลี่ยนแปลงต้องปรากฏเหมือนกันในทุกเครื่องที่ใช้งาน และผู้ใช้ทั่วไปยังเปิดลิงก์ได้ตามปกติ

## สภาพปัจจุบัน

- รายการเครื่องมือ 6 รายการและชื่อหมวด “เครื่องมือภายนอก” เขียนคงที่ใน `src/shell/Sidebar.jsx`
- Navigation ใช้ `activeTab` จาก `src/App.jsx` และ render เนื้อหาแต่ละหน้าตามค่านั้น
- ข้อมูลตั้งค่าร่วมที่เกี่ยวกับพนักงานเก็บใน Firestore `staffSettings` โดยอ่านได้สำหรับ operational staff และเขียนได้เฉพาะ Admin
- `firestore.rules` จำกัดเอกสารใน `staffSettings` แบบระบุ path; การเพิ่มเอกสารใหม่จึงต้องเพิ่ม rule แยก

## แนวทาง

เก็บการตั้งค่าทั้งหมดใน Firestore เอกสารเดียว `staffSettings/externalTools` และให้แอป subscribe เอกสารนี้หนึ่งรายการ เพื่อให้ Sidebar ทุกเครื่องรับชื่อและลิงก์ที่ Admin เปลี่ยนได้โดยไม่ต้อง deploy แอปใหม่

โครงข้อมูลหลัก:

```text
{
  groups: [
    {
      id: string,
      name: string,
      links: [{ id: string, label: string, url: string }]
    }
  ],
  updatedAt: server timestamp,
  updatedByUid: Firebase UID
}
```

เมื่อเอกสารยังไม่มี ให้ใช้ค่าเริ่มต้นจากรายการ 6 รายการปัจจุบันในหมวด “เครื่องมือภายนอก” โดยไม่เขียนเอกสารอัตโนมัติ การบันทึกครั้งแรกจาก Admin จะสร้างเอกสารร่วมชุดนั้น เมื่อมีเอกสารแล้ว แม้ `groups` จะเป็นรายการว่างก็ถือเป็นค่าจริงและต้องไม่ถูกแทนด้วยค่าเริ่มต้น

## ประสบการณ์ใช้งาน

- เพิ่มหน้า “ตั้งค่าเครื่องมือภายนอก” ใน navigation สำหรับ Firebase Admin เท่านั้น
- หน้า settings จัดการหมวดได้ครบ: เพิ่มหมวด เปลี่ยนชื่อหมวด และลบหมวดเดิมหรือหมวดใหม่
- แต่ละหมวดจัดการลิงก์ได้ครบ: เพิ่ม แก้ไขชื่อ/URL และลบลิงก์
- Sidebar แสดงหมวดและลิงก์ตามลำดับที่เก็บในเอกสาร ผู้ใช้ทั่วไปไม่เห็น control สำหรับแก้ไข
- การลบหมวดที่มีลิงก์ต้องแสดงการยืนยันพร้อมแจ้งว่าลิงก์ในหมวดนั้นจะถูกลบออกจากรายการร่วมด้วย การยืนยันจึงบันทึกการลบ
- ลิงก์ยังเปิดแท็บใหม่และใช้ `rel="noopener noreferrer"` ตามพฤติกรรมเดิม
- หากไม่ได้ตั้งค่า Firebase หรืออ่านเอกสารไม่สำเร็จ ต้องไม่สามารถบันทึกค่าที่โหลดไม่ครบ; Sidebar คงการตั้งค่าที่อ่านได้ล่าสุด หรือใช้ค่าเริ่มต้นเมื่อยังไม่มีข้อมูล และหน้า settings แสดงข้อความไทยพร้อมปิดการบันทึก

## ข้อมูลและสิทธิ์

- ผู้ใช้ที่เป็น operational staff อ่านเอกสารได้; เฉพาะ UID ที่มี `adminUsers/{uid}` จึงสร้างหรือแก้ไขเอกสารได้
- สิทธิ์ Admin ต้องตรวจจาก Firebase ไม่ใช้สถานะ Google Sheet `isSignedIn` แทน
- Firestore Rules ตรวจ path, keys ที่ยอมรับ, ชนิดข้อมูลหลัก, จำนวนหมวดสูงสุด, `updatedAt == request.time`, `updatedByUid == request.auth.uid` และ `isStaffAdmin()` สำหรับ create/update; ไม่อนุญาต delete เอกสาร
- Client validation จำกัดชื่อหมวดและชื่อ link ให้ไม่ว่าง, URL ให้ parse ได้และใช้ protocol `http:` หรือ `https:` เท่านั้น, URL ไม่เกิน 2,048 ตัวอักษร, หมวดไม่เกิน 10 และลิงก์รวมไม่เกิน 100 รายการ
- ถ้าเอกสารที่อ่านได้มีโครงสร้างไม่ถูกต้อง ให้ normalize/ปฏิเสธข้อมูลนั้นอย่างปลอดภัย ไม่สร้างลิงก์ที่มี protocol อื่น และห้าม fallback แล้วเปิดให้บันทึกทับข้อมูลที่อ่านไม่สำเร็จ
- การเขียนทั้งชุดใช้ `setDoc` หนึ่งครั้งบนเอกสารเดียวพร้อม server timestamp เพื่อให้การเปลี่ยนชื่อ/ลิงก์เป็น atomic

## ข้อผิดพลาดและความเข้ากันได้

- ข้อความ validation, permission และ save failure ที่ผู้ใช้เห็นต้องเป็นภาษาไทย และไม่แสดง response ภายในของ Firestore
- รักษาชื่อ, URL, การเปิดแท็บใหม่ และ `data-testid` ของลิงก์เริ่มต้นทั้ง 6 รายการ เพื่อให้ regression tests เดิมยังชี้เป้ารายการได้
- การไม่มี Firebase หรือการอ่านเอกสารไม่ได้ไม่ควรทำให้ Packer/Drive ที่ใช้ส่วนอื่นของแอปหยุดทำงาน; แสดงลิงก์ค่าเริ่มต้นตามเดิมและไม่เปิดความสามารถแก้ไข

## การตรวจรับ

- Unit tests ครอบ default config, normalization, CRUD ของ groups/links, protocol validation และขอบเขตจำนวนรายการ
- Firestore rules tests ยืนยันว่า operational staff อ่านได้ แต่ผู้ใช้ทั่วไปเขียนไม่ได้ และ Firebase Admin เขียน payload ที่ถูกต้องได้เท่านั้น
- E2E tests ยืนยันว่าค่าเริ่มต้นเดิมยัง render, Admin เพิ่ม/แก้/ลบหมวดและลิงก์ได้, ผู้ใช้ที่ไม่ใช่ Admin ไม่มีทางแก้ไข และการยกเลิกลบหมวดไม่เปลี่ยนข้อมูล
- ตรวจหน้าจอจริงทั้ง light/dark และ viewport 1280/1440/1920 ตาม `DESIGN.md`
- รัน `npm run test:marketplace` และ `npm run build` ก่อนรายงานผล
